# Routing rules

An execution unit declares role, capability and requirements, never harness or
model. Routing rules say which harness each kind of unit runs on. The decision
that created them is in [ADR-0002](adrs/ADR-0002-backend-dispatch-demerzel.md).

## Where they live

The instance belongs to the user: `$XDG_CONFIG_HOME/radiant/routing.json`, or
`~/.config/radiant/routing.json` without the variable. It is generated by the
machine's configuration manager, such as dotfiles, and stays outside any
project, because installed harnesses and subscriptions are facts about the
machine. Radiant defines the format and keeps an
[example](routing.example.json), checked by the validator.

## How they are applied

1. The orchestrator chooses, with judgment, the rule whose `when` describes
   the unit. Without a suitable rule, it uses `default`.
2. The dispatch operator walks the `use` candidates in order and discards
   those without a Radiant adapter or whose `adapters/<harness>/provides.json`
   does not cover the unit's `requires`.
3. The first viable candidate wins. The model comes from the adapter's
   `capabilities.json`, for the unit's capability or the candidate's.
4. The decision is recorded before launch and is not reread afterwards.

A candidate never uses a capability below the one the unit asks for. Without a
viable candidate, the unit stays in `HOLD`. An `effort` the harness does not
accept is recorded and left out of the launch. A rule with `approval: human`
only dispatches with explicit confirmation from the human.

## Format

| Field | Rule |
| --- | --- |
| `schema` | Exactly `1` |
| `rules` | List of rules, possibly empty |
| `rules[].id` | Kebab-case, unique |
| `rules[].when` | Non-empty natural language condition |
| `rules[].use` | Non-empty list of candidates, in order of preference |
| `rules[].approval` | Optional; only accepts `"human"` |
| `rules[].why` | Optional; a reason that helps choose |
| `default` | Non-empty list of candidates for units without a rule |
| candidate `harness` | Required; name of a directory in `adapters/` |
| candidate `capability` | Optional; `deep`, `standard` or `light` |
| candidate `effort` | Optional; reasoning level requested from the harness |
